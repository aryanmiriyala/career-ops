## Why you?

I’m strongest when a system has to prove its work instead of just looking right. In my Diff-Grounded PR Generation research, I built an LLM pipeline that generated pull request descriptions from commits, diffs, linked issues, and repository metadata, then checked the output against the actual code-change evidence. At SmartSolve, I use Codex and Claude Code daily, but I keep the workflow grounded by reading the code, running checks when possible, and keeping proprietary work isolated in Docker/devcontainers. That habit matches this role. I care about the loop, not just the model call.

I like that Viktor is trying to make an agent do real work inside the tools a company already uses, not just answer questions. I’ve built around similar instincts in LLM evaluation, RAG, Docker-based AI workflows, and this career-ops pipeline, where the agent has to create files, generate PDFs, pass parser checks, and update a tracker before the work counts as done.
