# Application Questions

Question: Why this role
Prompt: What draws you to this role, and what you would want to build first.

Answer:
I am drawn to this role because 8x feels like a real software systems problem, not just a social platform. There are creators, brands, campaign managers, content reviews, performance data, payouts, and product decisions all moving at once. That kind of environment fits the way I think as an engineer. I have worked across software, data, and AI systems, and my research has focused on AI for software engineering, especially how AI can help with software evolution, maintenance, and architecture without removing human judgment.

The first thing I would want to build is an AI-assisted product and engineering intelligence layer for 8x. It would connect campaign workflow signals, user pain points, product changes, and code history so the team can see where the platform is evolving, what is becoming hard to maintain, and what should be built or refactored next. My PR description generation research came from the same idea. Good software work depends on preserving context, and I would be excited to build that kind of context-aware system inside a fast-moving product like 8x.

Question: How do you use AI?

Answer:
AI is part of my normal engineering setup now, not just something I open when I am stuck. I mostly use Codex and Claude Code, and I am constantly testing new agent workflows as the tools change. For bigger work, I use tmux sessions and git worktrees so I can run parallel AI-assisted threads on separate branches, compare approaches, and keep the main implementation clean. I use AI for planning, code search, test generation, refactoring, PR review, and ticket writing, but I still treat myself as the person responsible for the architecture and final decision.

The part I have been most interested in lately is making AI workflows self-improving in a controlled way. I have been creating custom skills, routines, and hooks that help turn rough requirements into tickets, guide implementation, check the work, and reason about whether a PR is ready to merge. I think a lot about loops, memory, and feedback. If an agent misses a test, misunderstands a requirement, or writes a weak PR summary, that should become a better workflow next time instead of just a one-off correction. That connects directly to my AI4SE research on evidence-grounded PR descriptions. I do not see AI as just a way to generate code faster. I see it as a way to preserve context across software evolution, maintenance, and architecture so engineering teams can move quickly without losing the reasoning behind their systems.

Question: What is AI bad at?

Answer:
AI is still pretty weak at context management. It can look impressive on a single task, but once the context gets large, messy, or full of implied instructions, it starts dropping details that a human engineer would know are important. I see this a lot in coding workflows. Even when I explicitly mention a repeated requirement, like preserving a convention, checking a certain file, or applying the same fix across similar cases, the model can miss it later unless the workflow is structured very carefully.

That is one reason I am interested in AI for software engineering. The hard part is not only generating code. It is understanding why the code exists, what changed before, what pattern should be repeated, and which instruction matters most when the context window is crowded. I think future AI systems need much better memory, inference, and self-checking around long-running work. Until then, I treat AI as a powerful collaborator that needs strong routines, tests, and human review around it.

I want to join 8x because the product feels like the kind of messy, high-leverage system I like working on. It is not just a creator marketplace. There are brands, creators, campaign briefs, content review, performance tracking, payouts, and internal operations all depending on the software being clear and reliable. I am excited by AI, but I care most about using it to preserve context, improve decisions, and help teams move faster without losing judgment. 8x seems like a place where I could build close to the product, learn quickly from users, and work on systems where better software directly changes how people earn, collaborate, and run campaigns.
